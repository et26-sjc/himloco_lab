# Go1冲击预测：独立网络与共享Estimator的机制对照

设计日期：2026-11-08。2026-11-09起执行开发与正式实验，完成状态及结果由独立结果报告记录。承接[未来强落足计划](GO1_IMPACT_ANTICIPATION_PLAN.md)，不修改历史实验结果。

## 新信息改变了哪项归因

用户明确确认：旧实验的冲击head与原HIMEstimator的速度/latent共享trunk。此前Go1实验主要训练独立网络，证明本体历史可用于估计，不证明接到既有Estimator上同样有效。旧问题可能同时涉及目标、共享表征、优化与闭环，而非单一MSE损失问题。共享也可能带来有益迁移，负迁移只是待检验假设。

必须区分两种共享：原HIM速度/latent与冲击共享；独立ContactEstimator内的force/impact共享。本轮主研究明确采用前者。旧MC日志约1269及4439行记录了独立358→128→64→8 ContactEstimator及force/impact共享encoder，该段不能代表用户所指共享HIM版本；不将两个历史实现混同。后者仅作为其他共享形式的对应检查，不替换本轮主研究。

当前代码事实：

- [HIMEstimator](../source/himloco_lab/himloco_lab/rsl_rl/modules/him_estimator.py)的encoder为270→128→64→19，19维分为3维速度和归一化16维latent；中间64维与最终19维不是同一表征。
- HIM原损失为速度MSE与prototype/Sinkhorn swap loss。Actor调用该Estimator时停止梯度；当前实现的PPO梯度不经过HIM，不能预设存在PPO/impact梯度冲突。
- 本地UniFP的`adaptation_encoder_module`同时用于Actor和估计decoder；Actor路径没有detach，PPO与估计优化器均包含encoder。其权重在MSE前乘到预测与目标上，实际平方误差系数是该权重的平方。这些是实现差异，不是旧误差原因的证明。
- 冻结Actor权重但更新它使用的HIM，会改变Actor输入与动作，不等于冻结行为策略。

## 优先检验的假设

1. **表征限制**：为速度/locomotion训练的压缩表示是否遗漏精确加载所需的信息？最终归一化latent是否比64维中间层更不利？读出差只能说明所测head/预算下的信息可用性，不证明信息完全消失。
2. **多目标优化**：impact梯度是否受到HIM损失的方向、尺度或更新安排影响？共享是否反而改善未来预测？
3. **表征持续变化**：即使impact梯度被截断，HIM持续更新是否使head面对移动特征？这与静态冻结trunk是不同问题。
4. **用途与目标**：未来风险报警是否需要事件概率，而非连续严重度均值？这与BCE相对概率MSE的损失比较分开。
5. **闭环变化**：共同训练导致动作与接触分布改变，是否另有反馈效应？先不与前四项混测。

任务间梯度方向冲突是已知多任务问题，[PCGrad原论文](https://arxiv.org/abs/2001.06782)提供了一个干预参考；观测到负余弦本身不足以确诊本项目瓶颈，采用现有方法也不是本项目的新颖性依据。

## R0：固定轨迹上的机制检查

由完整冻结的原baseline JIT采集4096环境轨迹。训练网络都是影子副本，不向数据采集Actor写回权重；所有组读取同一训练、验证与测试轨迹、历史顺序和噪声。原JIT与HIM checkpoint均锁哈希。

共享原HIM时，需要额外记录原update所需的下一时刻速度真值及next-observation切片，准确保全terminal/reset边界。不得为方便重构swap target而使用reset后观测。旧impact缓存没有完整保存这些字段，不能假定可直接重现HIM联合训练；必要时小规模新采集。privileged字段只进入训练损失和离线审计。

共同未来主任务不变：当前历史预测未来80ms内下一次合格落足是否强加载；连续参考为该落足的严重度，无未来落足为0。未来标签需要80+40ms成熟，按原协议删失。另在同一开发轨迹构造已完成20ms的F20/L20/S20，作为训练管线的诊断；其高分不得替代未来主终点。

| 组 | trunk/impact head的更新 | 要隔离的条件 |
|---|---|---|
| A：专用副本 | 复制同一预训练HIM的270→128→64，只用impact目标更新，加新head | 与共享组具有相同初始特征和结构的单任务参考 |
| B：冻结表征 | 原HIM trunk固定，仅训练接在64维上的head | 现有特征不更新时是否足以读出目标 |
| C：联合共享 | 同一初始化，trunk同时接受HIM原损失和impact损失 | 增加原任务约束的影响，保留原19维速度/latent路径 |
| D：移动表征、截断impact梯度 | trunk只按HIM原损失更新；head读取detach后的64维并独立更新 | 与B比较移动特征影响，与C比较impact写回影响 |

A/C/D初始化的encoder、HIM原输出层、target/prototype（如使用）逐位相同；head在配对初始化下相同。A不使用HIM损失，不能因其原速度估计退化而判定impact失败。B/D在head之外的更新方式不同，须如实披露训练量；各组参数量、可训练参数量、样本曝光、反向计算与推理时间分开报告。

实现前必须核对梯度路由：HIM的forward/get_latent返回detach后的量，直接在该返回值后挂head不会让impact更新encoder；输入detach又不等于参数停止梯度。逐项核验每个loss可更新哪些参数。联合组使用一次合成损失更新，不让两个Adam重复更新同一trunk。复制checkpoint后保持原ELU、历史顺序和输入缩放，不将此前独立模型的额外z-score直接套入HIM；若变更输入归一化，须先等价变换首层并检验输出一致。

另做一个小型冻结读出诊断：从最终19维（3维速度+归一化latent）而非64维读出。读出head参数近似匹配并披露差异，不把19维head表现差直接写成不可逆信息瓶颈。原未来协议中的从头训练原始历史BCE/相位BCE仍保留；A是为归因新增的同初始化参考，不替换它们。

每组比较三种目标/损失：连续严重度MSE、同一未来事件标签的概率MSE/Brier、BCE。BCE与连续MSE比较的是目标及损失的组合，BCE与Brier才隔离二值目标下的评分形式。若原共享只在force/impact内部，先用force-only、event-only、force+event共享三个对应组，监督时窗和初始化一致；不额外引入HIM损失来冒充原结构。

物理目标先固定单位缩放（严重度除2000），还原物理单位报告误差。联合损失写为L_HIM+lambda L_impact；开发阶段用相同的lambda候选0.1/1/10及相同调参预算，记录实际梯度尺度，选点规则与最终lambda在正式测试前锁定。不能用某个未经调试的单一权重造成共享失败，再推广到多任务学习。

## R1：未来预测正式复验

沿用原N1的4096环境、五独立数据×两初始化、六训练家族/箱块留出及提速测试；匹配数据、采样与更新预算，初始60000次、batch2048，开发收敛后锁定。额外原HIM目标逐角色短期保存，不长期保留全量privileged observation。

原N1的唯一科学主比较仍为完整历史BCE对相位BCE的有效提前检出率，按最低提前量和无效动作预算验收。共享机制对照为新增次级研究，必须在打开新测试前单独锁定其模型、lambda与统计对比，不能事后提升为原主成功判据。

关键机制对比为C−A（同初始化下增加原任务的效果）、D−B（表征变化）、C−D（impact写回）。报告三种损失下的成对差及数据组置信区间；若要作确认性多重比较，预先指定单一对比或进行Holm校正，不在多个时窗/损失/域中挑显著值。分类相对回归的优势是否因共享增大，用“共享中的差−专用中的差”的交互对比，不能只比较两列各自是否显著。

同时报告力/严重度物理误差、尾部、事件AP/Brier、有效提前检出率/无效动作、HIM速度误差、swap loss和固定历史上的原Actor动作偏移。latent坐标差不是语义损失的充分指标；最终是否损害行走，仍须后续独立闭环评价。

固定开发批次按层记录impact与速度、swap梯度的范数和余弦，以及clip前后变化；若后续有PPO接入再新增PPO梯度项。负余弦只作诊断；只有受控调整权重、停止共享或预先锁定的梯度处理能恢复表现，才加强对该机制的归因。

## 如何根据结果继续

| 结果 | 支持的判断与下一步 |
|---|---|
| A好、B差 | 专用适配有价值；比较更早层读出或小私有支路，尚不能仅凭此证明信息丢失 |
| A/B好、C差，且权重/梯度处理恢复 | 加强联合优化受干扰的解释，继续检查原任务代价 |
| B好、D差 | HIM持续更新造成的特征非平稳值得优先处理，不能简单称输入分布遗忘 |
| C与A相当或更好 | 共享未必是旧实验原因，可能有正迁移；再核查旧标签/尺度/闭环条件 |
| 连续MSE只有共享时明显落后 | 支持当前配置下回归更受共享条件影响，不能推广为所有回归更难 |
| A在未来任务也失败、当下诊断成功 | 先研究有效提前量、隐藏地形和传感信息，不靠共享结构解释全部失败 |

若确有共享瓶颈，可检验“保留原HIM路径、冲击使用受限私有支路”的小模块。只在冻结64维后加adapter不能保证恢复此前未编码的信息，必要时从128维或原始历史接入，并与同参数独立网络比较。PCGrad/损失平衡仅作已有方法对照，不预设为创新或默认有效。

Replay在上述未来能力建立后接入：存因果原始历史及成熟标签，避免只存随trunk变化而过期的特征。若联合更新HIM，还需明确是否保留原任务监督或采用冻结教师约束，并报告记忆字节；不能声称只回放impact head就保证原HIM不漂移。

完成固定轨迹机制判断后，再决定是否把候选Estimator接回冻结Actor，并开展原N0/N3动作时间与收益检查。接回后行为已改变，需独立闭环轨迹和配平对照，不能继续宣称数据分布固定。

## 2026-11-09执行细化：正式测试开启前

- 可执行协议为[shared_anticipation_v1.json](../configs/impact/shared_anticipation_v1.json)，启动器`python scripts/impact/run_anticipation.py`，环境`himloco_lab`。
- 开发数据为4096环境×800/400策略步，seed9500/9550。15000更新后验证损失仍下降，使用相同optimizer/RNG继续到60000；正式采用60000、batch2048，不按测试延长个别模型。
- 每复制保留三档联合权重的完整敏感性对照，共44个影子模型及2个相位模型，即46个；五复制共230个未来模型。主要联合权重仅按开发验证role0、两个初始化平均的本目标损失选择，其他权重不能在测试后替代为主比较。
- 64维读出head为64→64→4。19维补充诊断使用相同分配的head、19维零填充；有效head参数1540，对比64维4420，不能单据此证明压缩造成信息丢失。核心四组的64维head相同。
- 第一复制另做同轨迹、已完成20ms的最大平滑loading-rate诊断，仍为46个模型；仅是一组数据的阳性诊断，不冒称五复制的当前任务结论。标签还保存平均力/末端平滑率供物理审计，当前回归head本身预测的是最大平滑率。
- 全部主统计扣除统一5ms主机推理时间预算，再加0/10/20ms额外链路延迟。开发batch1 TorchScript同步实测的最大架构p99约1.12ms；正式每复制复测须p99≤5ms。该预算不是硬实时保证，也不是Go1机载实测。
- 本轮主终点是力阈值起点前的风险预测；尚无几何接触及执行器响应验收。原N0物理作用检查移至影子网络机制判断之后，不把20ms研究档位宣称为已验证可干预提前量。
- 在所有复制模型、开发选择及验证工作点锁定后才采集最终测试。原生标签独立复算、完整输入fixture重新推理、稀疏报警重新计数后清理bulk数组，保留校验清单。
