## 训练命令的准确含义

采用原实际训练快照 `provenance/training_env.yaml`：x、y初始采样范围均[-1,1] m/s，yaw范围[-2,2] rad/s；x课程上限[-2,2]。`min_command_norm=0.2`在自定义 `_resample_command` 中将二维平面速度模长不超过0.2的 **x、y一起置零**。

这意味着训练中没有0到0.2之间的非零**平面合速度模长**，仍有零平面速度命令；某一轴分量小于0.2同时另一轴较大也会出现。它不是yaw的最小值，也不是单独vx、vy的下限。训练启用了heading命令，不能据yaw范围断言所有角速度的训练覆盖程度相同。

### 后台启动

确认上一轮已停止且机身可靠承托，旧终端A按Ctrl+C结束旧桥接，然后：

```bash
sudo bash /home/unitree/go1_lab_deploy/start_background.sh
tail -f /home/unitree/go1_lab_deploy/logs/latest_policy.console.log
```

启动脚本要求一次Enter确认。保持遥控器摇杆居中，等`WAIT_R2`后第一次按R2标定；等`READY`后松开再按R2接管。`RUNNING`后遥控器继续控制，L2任何阶段停止；运行中R2停止，停止后不自动重启。

桥接使用`nohup setsid`和独立标准输入；Docker客户端同样脱离SSH，但不用`-it`。后台模式下关闭SSH或`tail -f`里的Ctrl+C不会停止控制；不得沿用前台“Ctrl+C当前终端就是停止策略”的理解。

### 查看和停止

```bash
sudo bash /home/unitree/go1_lab_deploy/status_background.sh
sudo bash /home/unitree/go1_lab_deploy/stop_background.sh
```

先用遥控器使机器人停止运动并承托机身，再结束控制。停止脚本匹配本发布的容器标签和桥接真实路径，先向容器发送SIGINT，策略结束后再SIGTERM桥接。若SSH已经断开，使用遥控器L2或运行中R2；SSH重连后再清理桥接。零增益停止不维持站立。

状态脚本显示bridge PID、容器宿主机PID、CPU／内存、最近输出以及`top -p`命令。`ps %CPU`是进程生命周期的平均值，`top`／`docker stats`用于查看当前占用。JIT推理耗时不能直接替代CPU占用率；本次没有运行提速策略来采集资源。

### 网线

本机SDK路由：`192.168.123.10 dev eth0 src 192.168.123.250`；电脑SSH地址`192.168.123.15`在eth1。初始还有`224.0.0.0/4 dev eth1`，LCM组播实际走eth1，**单纯nohup仍不足以保证拔线后通信**。

因此`start_background.sh`在旧控制程序已结束、8090未占用的条件下，先调用`scripts/prepare_background_network.sh`：读取配置中的组播地址，给本组添加更具体的主机路由（本机为`239.255.76.67/32 dev eth0`），再创建桥接和策略的LCM套接字。默认路由、SSH路由和MCU单播路由均不改；修改前路由记录在`logs/lcm_route_before_background.txt`。该路由保留到重启，后台入口每次显式配置；不是开机服务。

确认后台`RUNNING`和遥控停止有效后，可以断开电脑到Go1的外部网线。机器人内部MCU链路和Jetson供电必须保留。若拔线后机器人状态或遥控过期，现有保护仍锁存停止。组播接口切换必须在旧桥接停止后、新套接字创建前进行，不能对着运行中的控制器直接改路由。
